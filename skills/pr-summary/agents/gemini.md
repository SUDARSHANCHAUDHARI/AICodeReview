# PR Summary

When asked to write a PR summary, follow this workflow:

1. Inspect branch, base branch, changed files, and git diff.
2. Read nearby code and docs only as needed to understand user-facing impact.
3. Summarize what changed, why, and how it was verified.
4. Do not push, create PRs, or change repo settings unless explicitly asked.

Output format:
- Summary (bullet points)
- Testing checklist
- Notes for reviewers

Keep it concise and concrete. No marketing language.
