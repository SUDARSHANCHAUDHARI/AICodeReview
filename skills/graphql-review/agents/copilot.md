When asked to review GraphQL code: read all schema files (.graphql, .gql, or inline schema definitions) and map all types, fields, queries, mutations, and subscriptions; check naming conventions (types PascalCase, fields camelCase, enum values SCREAMING_SNAKE_CASE); check nullability design (non-null on stable required fields, nullable on legitimately absent data); read all resolver files and flag N+1 patterns where list resolvers issue a separate DB or service query per parent item without a DataLoader or batch function; check that sensitive fields (PII, admin data, private resources) have field-level auth checks in resolvers not just at the route middleware level; check input validation on all mutation inputs for type, range, length, and format constraints; verify the server has query depth and complexity limits configured; check subscription resolvers for cleanup on disconnect; identify breaking schema changes (removed fields, changed field types, added required arguments, renamed types) and flag any without a prior deprecation period; check pagination consistency (cursor-based vs offset) and flag mixing without documented reason; output all findings ordered P0 (auth gap on sensitive field, N+1 on high-traffic resolver, breaking change without deprecation) through P3 (minor naming deviation, documentation gap) with file:line and a one-sentence fix for each finding.
