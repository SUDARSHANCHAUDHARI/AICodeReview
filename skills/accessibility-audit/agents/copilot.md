## Accessibility Audit

When asked to audit accessibility: check all non-text content has a text alternative (alt/accessibilityLabel/contentDescription), colour not the only means of conveying info, contrast ≥4.5:1 normal/≥3:1 large text, all interactive elements keyboard-reachable with visible focus indicator, no keyboard traps, touch targets ≥44×44pt (iOS)/48×48dp (Android)/44×44px (web), form inputs have programmatically associated labels (not just placeholders), error messages identify the field and describe the fix, semantic HTML used (`<button>` not `<div onClick>`, correct heading hierarchy), ARIA used only when native semantics insufficient, focus managed on modal open/close and route changes, dynamic content announced via aria-live. Rate findings P0–P3. P0=prevents task completion, P1=significant barrier, P2=WCAG failure, P3=polish.
